處理合併衝突：同一條筆記喺兩部裝置度都改過

當你喺兩部裝置度將同一條 JW Library 筆記改到唔同咗，合併就一定要揀一個贏家。衝突檢視會將兩個版本並排擺出嚟，由你決定——乜都唔會少。

合併嘅絕大部分都好輕鬆——每部裝置獨有嘅筆記直接匯埋一齊。唯一要做決定嘅情況係真正嘅衝突：同一條筆記，喺兩部裝置度被改到唔同咗，於是兩個備份對佢應該寫乜各執一詞。JW Sync 永遠唔會靜靜雞幫你估，佢將呢個選擇交返畀你。

一步一步做

  1. 將兩個備份都載入

    喺 jwsync.org 載入兩部裝置嘅 .jwlibrary 檔案。JW Sync 會喺合併嘅同時將佢哋對比一次。

  2. 打開衝突檢視

    如果有筆記撞咗，檢視介面會將佢哋列出嚟。冇撞嘅一切都已經合併好——呢一步淨係針對真係撞咗嗰啲。

  3. 並排對比

    每個衝突都會顯示兩個版本，用逐個字嘅分別準確標出邊度唔同。「建議較好嗰個」可以幫你揀內容較完整嗰個，你亦可以自己揀留邊個——逐條決定。

  4. 完成再還原

    所有衝突解決完之後，下載合併好嘅檔案再還原佢。兩部裝置而家意見一致，每條筆記都係你揀定嗰個版本。

而家就試——免費，喺瀏覽器度做晒JW Sync 完全喺你部裝置度合併、編輯同分析 .jwlibrary 備份。唔使帳號，唔使上載，亦都唔使裝任何嘢。開啟 JW Sync →

點解呢個好過「淨係留最新嗰個」

「最新嗰個贏」會靜靜雞刪走一啲你可能想留嘅改動。可能舊版本入面有一段，係你喺另一部裝置度撳錯刪咗嘅。將兩個版本逐個字擺出嚟睇，即係話你永遠唔會喺唔知情之下冇咗啲文字——而呢個正正就係「合併」而唔係「冚過去」嘅全部意義。

衝突一開始係點嚟嘅

通常係因為喺兩次合併之間、喺兩部裝置度離線改嘢，又或者還原咗一個舊備份之後再加嘢上去。按固定節奏合併，可以令衝突嘅數量保持得好少，亦令嗰啲分別喺你記憶入面仲係新鮮嘅。

常見問題

我會唔會要睇幾百個衝突？
好少見。只有兩邊都改過、而且改法唔同嘅筆記先會撞；新筆記，同埋淨係喺一部裝置度改過嘅筆記，都會自動合併。大部分合併得寥寥幾個衝突，甚至一個都冇。
揀完之後我可唔可以反悔？
可以——喺你還原合併好嗰個檔案之前，乜都唔會寫入部裝置，而你原本嘅備份亦絕對唔會被改動，所以你隨時可以重做呢次合併。
