Paano mag-import ng mga talang Markdown sa JW Library

Gawing tunay na tala ng JW Library ang mga .md file mula sa Obsidian, Notion o kahit anong Markdown editor, nakalapat sa tamang talata — libre, pribado, sa loob ng browser mo.

Walang paraan ang JW Library para magpasok ng teksto. Puwede kang sumulat ng tala sa loob ng app, pero ang talang isinulat sa ibang lugar — sa Obsidian, sa Notion, sa isang plain text file sa computer — ay walang anumang daan papasok sa aklatan mo. Nagre-retype ang mga tao, o sumusuko na lang at nagkakaroon ng dalawang set ng talang pag-aaral na hindi nagtatagpo kailanman.

Sinasara ito ng JW Sync. Mag-load ng backup sa Study Explorer, pindutin ang “Mag-import ng Markdown”, at magiging tunay na tala sa loob nito ang mga .md file mo: buo ang pamagat, petsa at mga tag — at kapag sinasabi ng file kung saang teksto ito nauukol, nakakabit ito sa mismong talatang iyon, na parang isinulat mo ang tala sa app habang binabasa mo ito.

Gumagana ito sa dalawang direksyon. Ang mga talang na-export mula sa site na ito ay may dalang aklat, kabanata at talata, kaya bumabalik sila nang tumpak sa pinanggalingan nila. Ang mga talang isinulat sa ibang lugar ay karaniwang wala nito, kaya ipinapaliwanag ng pahinang ito ang isa o dalawang linyang naglalapat sa kanila — at kung ano ang mangyayari kapag wala ang mga iyon sa file.

Hakbang-hakbang

  1. Gumawa ng backup sa JW Library

    Buksan ang JW Library, pumunta sa Personal na Pag-aaral, pindutin ang tatlong-tuldok na menu, piliin ang Backup and Restore, tapos Create a backup. Magkakaroon ka ng .jwlibrary file — ang aklatang pagdadagdagan ng mga tala mo.

  2. Buksan ang Study Explorer

    Pumunta sa jwsync.org, buksan ang Study Explorer at i-load ang .jwlibrary file na iyon. Lahat ay nangyayari sa loob ng browser mo; hindi kailanman ina-upload ang file.

  3. Pindutin ang “Mag-import ng Markdown”

    Nasa tabi ito ng “I-export ang Markdown”. Pumili ng kahit ilang .md file, o ng isang .zip na naglalaman ng mga ito — pati na ang .zip na ginagawa ng site kapag nag-export ka.

  4. Basahin ang buod bago may maisulat

    Sinasabi sa iyo kung ilan ang dadapo sa isang talata, ilan ang idadagdag bilang malayang tala, at ilan ang nasa backup mo na kaya lalaktawan. Anumang kinailangang bigyang-kahulugan ng site ay nakalista isa-isa, may kahon na matsetsekan, kaya ikaw ang magpapasya sa halip na matuklasan mo na lang pagkatapos.

  5. Mag-export at mag-restore

    Pindutin ang “I-export ang .jwlibrary”, tapos i-restore ang file na iyon sa JW Library sa pamamagitan ng Backup and Restore → Restore. Bahagi na ng aklatan mo sa device na iyon ang mga na-import na tala.

Ang pinakamaikling file na gumagana

Walang kailangan ang isang Markdown file para ma-import: ang file na puro teksto lang ay nagiging tala rin, at kinukuha ang pamagat mula sa unang heading o, kung wala, sa pangalan ng file. Ang lahat ng iba pa ay para sabihin kung saan nauukol ang tala. Ganito ang isang kumpletong file: --- title: Ang kopang ipinanalangin niya tags: [pag-aaral, getsemani] publication: Matthew 26:39 --- Pagpapasakop ang ipinapakita ng panalangin niya, hindi pag-aatubili. Ang bahagi sa pagitan ng dalawang linya ng gitling ay tinatawag na front matter. Ang mga linya sa ibaba nito ang mismong tala.

Ang mga field na binabasa

Limang bagay lang ang binabasa, at bawat isa ay tumatanggap ng ilang baybay para hindi mo na kailangang tandaan ang eksaktong pangalan. Ang **title** (o name, heading) ang nagiging pamagat ng tala. Ang **tags** (o tag, keywords, categories, labels, topics) ay nagiging tunay na tag ng JW Library, at ginagawa kung wala pa. Ang **date** (o created, modified) ang nagtatakda ng petsa; nauunawaan ang anumang naglalaman ng YYYY-MM-DD. Ang **publication** (o pub, reference, ref, scripture, citation, source, passage) ang lalagyan mo ng teksto. Ang **book**, **chapter** at **verse** (o ch, v, vs, verses) ay ganoon din, hiwa-hiwalay lang ang field. Ang anumang ibang field na itinatago mo para sa sarili mong gamit — may-akda, katayuan, kung ano ang idinadagdag ng editor mo — ay hindi pinapansin sa halip na ituring na mali.

Tatlong paraan para ituro ang tala sa isang talata

Isulat ang teksto sa isang linya: `publication: Matthew 26:39`. O hatiin: `book: Matthew`, `chapter: 26`, `verse: 39`. O gamitin ang dalawa — iyan ang ginagawa ng export ng site na ito, para madaling basahin ng tao at eksaktong mabasa ng makina. Pareho ang resulta ng tatlo, kaya gamitin kung alin ang bagay sa editor mo.

Gaano kaluwag ang pagbasa sa teksto

Maluwag ang pagtutugma sa pangalan ng aklat. Gumagana ang buong pangalan, gayundin ang mga daglat na talagang tinitipa ng mga tao: Matt, Matt., Mt, 1 Cor, 1Cor, I Corinthians, Second Timothy, Psalm pati Psalms, Song of Songs pati Song of Solomon. Ang pagitan ng kabanata at talata ay puwedeng tutuldok, tuldok o ang titik v — pareho ang pagbasa sa `John 3:16`, `John 3.16` at `1 Cor 13 v4`. Opsyonal ang mga espasyo, kaya tanggap din ang `1Cor13:4`. Ganoon din kaluwag ang front matter mismo. Puwedeng malaki ang unang titik ng mga field. Puwedeng walang espasyo pagkatapos ng tutuldok. Hindi pinapansin ang sobrang espasyo at tab, ang panipi sa paligid ng halaga, at ang # komento sa dulo. Walang problema ang mga line ending ng Windows. Puwede mo pang tanggalin nang tuluyan ang mga linyang --- at simulan ang file mismo sa mga field, basta ang pinakaunang linya ay isa sa mga kilalang pangalan — umiiral ang panuntunang ito para ang talang nagsisimula sa ordinaryong pangungusap na may tutuldok ay hindi mawalan ng unang talata.

Mga tag, kahit paano mo isulat

Lahat ng ito ay nagbubunga ng parehong dalawang tag: `tags: [pag-aaral, griyego]`, `tags: pag-aaral, griyego`, `tags: pag-aaral; griyego`, `tags: #pag-aaral #griyego`, o isang listahan sa sariling mga linya sa ilalim ng `tags:` na ang bawat entry ay nagsisimula sa gitling. Ang mga tag na nasa aklatan mo na ay ginagamit ulit sa halip na dumoble, kaya sumasama ang na-import na tala sa mismong tag na ginagamit mo nang pang-filter.

Ano ang nangyayari kapag may hindi malinaw

Walang pinagdududahang bagay na ipinapasya para sa iyo. Kung ang pangalan ng aklat ay malapit sa totoo pero hindi eksakto — `Mathew`, `Ecclesiates` — hindi awtomatikong inilalapat ang tala. Lumilitaw ito sa buod sa sariling linya nito na sinasabi kung paano binasa ng site: “binasa bilang Matthew 26:39”, may kahon na matsetsekan. Alisan ng tsek at hindi ito isasama; iwanang nakatsek at pupunta ito kung saan sinasabi ng linya. Kung hindi talaga makilala ang aklat, sinasabi iyon ng linya at idinadagdag ang tala bilang malayang tala — hindi kailanman pinipilit sa isang hula. Pinapanatili ng bilang na aklat ang bilang nito, kaya ang `1 Jonh` ay maitatama lang bilang 1 Juan, hindi kailanman 2 Juan.

Ang sinasadyang hindi nito ginagawa

Ang saklaw ng talata ay nakaangkla sa unang talata: inilalagay ng `Matthew 26:39-41` ang tala sa talata 39, dahil ang tala sa JW Library ay nakakabit sa isang punto ng teksto at hindi sa isang saklaw. Ang tekstong may kabanata pero walang talata — `Matthew 26` — ay ikinakabit sa kabanatang iyon. Ang file na nagbabanggit ng publikasyon sa halip na teksto — `The Watchtower—2023 No. 4` — ay ini-import bilang ordinaryong malayang tala nang walang itinatanong, dahil iyon mismo ang isinusulat ng export ng site para sa mga talang kinuha sa isang artikulo.

Ang pormat na nakakaligtas sa biyahe

Ang mga talata, line break, **bold**, *italic* at bulleted list ay dumarating bilang tunay na pormat sa JW Library. Ang heading sa itaas ng file ay ginagamit bilang pamagat ng tala sa halip na ulitin sa loob. Ang anumang kayang ipahayag ng Markdown na hindi kaya ng tala sa JW Library — mga talahanayan, larawan, link, code block — ay pinapaliit sa teksto nito, kaya walang salitang nawawala kahit hindi madala ang ayos.

Kung saan talaga napupunta ang mga tala, at bakit ligtas iyon

Para ikabit ang tala sa isang talata, kailangan ng JW Library ang mga panloob na identifier para sa kabanatang iyon na natatangi sa aklatan mo. Hindi kailanman ito iniimbento ng JW Sync. Ginagamit nito ang lokasyong mayroon na ang sarili mong backup para sa kabanatang iyon, o kinokopya ang mga identifier na iyon mula sa ibang lokasyon ng Bibliya sa loob ng parehong file. Kung ang backup ay walang anumang tala o highlight sa Bibliya, walang makokopyahan — kaya idinadagdag ang mga tala bilang malayang tala sa halip na ikabit sa isang bagay na baka hindi makilala ng app. Sinadya ito: mas masahol ang talang tahimik na napunta sa maling lugar kaysa sa talang malinaw na dumating na walang kabit.

Pag-import ng parehong file nang dalawang beses

Itinuturing nang nandiyan na ang tala kapag tugma ang pamagat, teksto at kinalalagyan nito sa isang bagay sa backup, kaya ang muling pag-import ng parehong export ay hindi dumodoble ng anuman. Sinasabi ng buod kung ilan ang lalaktawan dahil doon bago ka magkumpirma. Ang lahat ng idinadagdag ng isang import ay iisang hakbang ng Undo, at may tag na Imported ang mga na-import na tala para mahanap, ma-filter o matanggal mo sila nang sabay-sabay pagkatapos.

Mga madalas itanong

Kailangan ko bang gamitin ang mga linyang ---?
Hindi. Ginagawa nilang malinaw ang file at naiintindihan ito ng bawat Markdown editor, pero puwede mo ring simulan ang file mismo sa mga field — `title: …` sa unang linya — o laktawan ang front matter at hayaang kunin ng tala ang pamagat mula sa unang heading.
Paano kung mali ang baybay ko sa pangalan ng aklat?
Karaniwang nauunawaan ng site ang ibig mong sabihin, pero hindi ito kumikilos batay lang doon. Lumilitaw ang tala sa buod na may nakasaad kung paano ito binasa, may kahon na matsetsekan, kaya ikaw ang magkukumpirma bago may maisulat.
Puwede bang mag-import ng buong folder mula sa Obsidian?
Pumili ng kahit ilang .md file nang sabay, o i-zip ang folder at piliin ang .zip. Ang mga file sa loob ay binabasa katulad ng mga hiwalay na file.
Mapapalitan ba ng import ang mga talang mayroon na ako?
Hindi. Nagdaragdag lang ang import. Hindi ginagalaw ang kasalukuyang mga tala, highlight, bookmark at tag mo, at hindi kailanman binabago ang file na ni-load mo — isang bagong .jwlibrary ang ida-download mo sa dulo.
Ina-upload ba ang mga tala ko kahit saan?
Hindi. Sa browser mo tumatakbo ang lahat, tulad ng iba pang bahagi ng site. Hindi umaalis sa device mo ang backup at ang mga Markdown file mo.
Anong wika ang puwede kong gamitin sa teksto?
Sa ngayon ay Ingles ang pagkilala sa pangalan ng aklat, na siya ring isinusulat ng export. Kung sa ibang wika ka sumusulat ng tala, gamitin ang `book`, `chapter` at `verse` na may pangalang Ingles ng aklat, o i-import ang mga tala nang walang kabit at ilagay sa lugar nang manu-mano mamaya.
Mailalabas ko ba ulit ang mga tala ko?
Oo — ang “I-export ang Markdown” sa parehong screen ay isinusulat ang bawat tala sa isang .md file na may parehong field, kaya makakalabas ang mga tala sa JW Library at makakabalik nang hindi nawawala kung saan sila nauukol.
