Paano gumawa ng Markdown file na puwedeng i-import sa JW Library

Sumulat ng tala sa Notepad, TextEdit o Obsidian at ihulog ito sa tamang teksto sa JW Library. Ang eksaktong mga linyang ita-type, at lahat ng puwede mong laktawan.

Kayang basahin ng JW Sync ang mga Markdown file papasok sa isang backup ng JW Library, at iyon ang nagdudulot ng tanging tanong na talagang mahalaga kapag alam mo nang may ganitong tampok: ano ba dapat ang itsura ng file? Sinasagot ito ng pahinang ito mula sa panig ng sumusulat — hindi kung ano ang tinatanggap ng pag-import, kundi kung ano ang aktuwal mong tini-type.

Sa maikling salita, ang isang tala ay isang text file. Gumawa ng file, isulat ang tala, i-save nang nagtatapos sa .md, at mai-import na iyon. Ang lahat ng iba pa rito ay tungkol sa isang opsiyonal na linya: iyong nagsasabi kung saang teksto nabibilang ang tala, para lumitaw ito sa JW Library habang binabasa mo ang tekstong iyon sa halip na maiwang nakahiwalay sa gitna ng iba mong tala.

Wala rito ang nangangailangan ng Markdown editor, at wala ring nangangailangan na matuto ka ng Markdown. Sapat na ang Notepad sa Windows at TextEdit sa Mac. Kung nasa Obsidian o Notion na ang mga tala mo sa pag-aaral, Markdown na ang mga file na iyon, at may sariling bahagi ang bawat isa sa ibaba.

Hakbang-hakbang

  1. Magbukas ng kahit anong plain text editor

    Notepad sa Windows, TextEdit sa Mac, o ang Markdown app na ginagamit mo na — Obsidian, Typora, iA Writer, Joplin. Ang tanging dapat iwasan ay word processor: nagse-save ang Word at Google Docs ng anyo at disenyo sa halip na plain text, at wala sa dalawa ang gumagawa ng file na kayang basahin ng pag-import.

  2. I-type ang tala

    Ilagay ang pamagat sa unang linya na may # sa unahan, mag-iwan ng blangkong linya, at isulat ang tala sa ibaba. Kumpleto at wasto nang file iyon. Kung ayaw mong magsulat ng linya ng pamagat, ang pangalan ng file ang gagamitin.

  3. I-save ito nang nagtatapos sa .md

    Pangalanan mo kung ano ang gusto mo — aking tala.md. Sa Windows, .txt ang isi-save ng Notepad hangga't hindi mo muna binabago ang “Save as type” tungo sa “All Files”, at iyan ang pinakamadalas na mapagkamalian. Sa Mac, piliin ang Format at pagkatapos ang Make Plain Text bago mag-save.

  4. Idagdag ang linyang naglalagay nito sa isang teksto

    Sa pinakaitaas ng file, bago ang lahat, magsulat ng linyang may tatlong gitling, tapos publication: Matthew 26:39, tapos tatlong gitling ulit. Nakakabit na ngayon ang tala sa tekstong iyon. Kung laktawan mo ito, mai-import pa rin ang tala — dumarating lang itong walang kakabitan.

  5. I-import ito sa isang backup

    Sa JW Library, pumunta sa Personal na Pag-aaral, buksan ang tatlong-tuldok na menu, piliin ang Backup and Restore at gumawa ng backup. I-load ang file na iyon sa jwsync.org, sa Study Explorer, pindutin ang “Mag-import ng Markdown”, piliin ang iyong mga .md file, at basahin ang buod na ipapakita bago may maisulat. Pagkatapos, pindutin ang “I-export ang .jwlibrary” at i-restore ang file na iyon sa JW Library.

Ang pinakamaikling file na gumagana

Ang file na walang laman kundi teksto ay wasto nang tala. Ito lang ang buong laman:

# Ang kopang ipinanalangin niya

Pagpapasakop ang ipinapakita ng panalangin niya, hindi pag-aatubili.

Ang linyang nagsisimula sa # ang nagiging pamagat ng tala, at lahat ng nasa ilalim nito ang nagiging tala. Nai-import ang file na iyon nang walang reklamo. Dumarating lang itong nakahiwalay na tala, kasama ng iba mong tala sa halip na nakakabit sa isang teksto.

Paggawa ng file sa Windows

Buksan ang Notepad, i-type ang tala, tapos piliin ang File at Save as. Bago mag-save, baguhin ang “Save as type” mula “Text Documents” tungo sa “All Files” — kung walang hakbang na iyan, tahimik na idadagdag ng Notepad ang .txt at ang matitira sa iyo ay aking tala.md.txt, na hindi makikita ng pag-import. Pagkatapos, i-type ang pangalan na nagtatapos sa .md. Baka magbabala ang Windows na maaaring hindi na magamit ang file kapag pinalitan ang extension; ang babalang iyon mismo ang tanda na tama ang ginawa mo.

Paggawa ng file sa Mac

Buksan ang TextEdit at piliin ang Format at pagkatapos ang Make Plain Text bago mag-type ng kahit ano. Nagsisimula ang TextEdit sa rich text mode at nagse-save ng .rtf, na hindi naman talaga text file. Kapag nasa plain text mode na, piliin ang File at Save, at tapusin ang pangalan sa .md. Kung mag-alok ang macOS na idagdag ang .txt, tanggihan mo.

Paggawa ng file sa telepono o tablet

Puwede ang kahit anong app na kayang mag-save o mag-export ng Markdown — Obsidian, Bear, iA Writer, Joplin, Markor sa Android. Karaniwang hindi kayang mag-save ng .md file ng mga Notes app na kasama na sa iPhone at Android, kaya sa telepono, ang karaniwang daan ay isa sa mga app na iyon, o basta't magsulat na lang sa kompyuter. Kapag nag-import ka, puwede kang pumili ng kasindami ng gusto mong file nang sabay-sabay, at puwedeng i-zip ang buong folder at ibigay bilang isang .zip.

Ang isang linyang naglalagay ng tala sa isang teksto

Lahat ng nagsasabi sa pag-import kung saan nabibilang ang tala ay nasa maliit na bloke sa pinakaitaas ng file, sa pagitan ng dalawang linya ng tatlong gitling. Tinatawag itong front matter, at sa karamihan ng tala ay isang linya lang ito:

---
publication: Matthew 26:39
---

# Ang kopang ipinanalangin niya

Pagpapasakop ang ipinapakita ng panalangin niya, hindi pag-aatubili.

Nakakabit na ngayon ang talang iyon sa Mateo 26:39. Lumilitaw ito sa JW Library habang binabasa mo ang tekstong iyon, gaya mismo ng kung isinulat mo ito roon sa app.

Pagsulat ng reperensiya nang maiintindihan

Isulat sa Ingles ang pangalan ng aklat, kahit iba ang wika ng mismong tala: Matthew, hindi Mateo. Naiintindihan din ang mga daglat na talagang tini-type ng mga tao — Matt, Matt., Mt, 1 Cor, 1Cor, I Corinthians, Second Timothy. Sa pagitan ng kabanata at teksto, puwedeng tutuldok, tuldok, o ang letrang v, kaya iisa ang ibig sabihin ng John 3:16, John 3.16 at 1 Cor 13 v4, at opsiyonal ang mga espasyo, kaya puwede rin ang 1Cor13:4. Ang saklaw na gaya ng Matthew 26:39-41 ay naglalagay ng tala sa unang teksto, ang 39, dahil ang tala sa JW Library ay kumakabit sa isang punto ng teksto at hindi sa isang saklaw.

Ang buong file, may pamagat, petsa at tag

May tatlo pang linyang puwede kung gusto mo, at opsiyonal silang lahat:

---
title: Ang kopang ipinanalangin niya
date: 2026-08-15
tags: [pag-aaral, getsemani]
publication: Matthew 26:39
---

Pagpapasakop ang ipinapakita ng panalangin niya, hindi pag-aatubili.

Ganoon din ang ginagawa ng title gaya ng ulong may #, kaya isa lang sa dalawa ang kailangan. Itinatakda ng date ang petsa ng tala sa halip na iwan ang araw ng pag-import. Nagiging tunay na tag sa JW Library ang tags na puwede mong pagsalain, at ang tag na mayroon ka na ay ginagamit ulit sa halip na doblehin. Puwede ring isulat ang linyang tags bilang pag-aaral, getsemani nang walang panaklong, o #pag-aaral #getsemani, o bilang listahang may gitling sa magkakahiwalay na linya sa ibaba — pare-pareho ang basa sa apat.

Isang tala bawat file

Nagiging isang tala ang bawat .md file. Walang paraan para maglagay ng ilang tala sa iisang file at paghiwa-hiwalayin sila, dahil walang anuman sa isang Markdown file ang maaasahang nagtatanda kung saan nagtatapos ang isang tala at nagsisimula ang susunod — ang ulo sa gitna ay puwedeng pangalawang tala o puwede ring pang-ilalim na ulo ng una, at kung mali ang hula ay makakalat ang isinulat mo. Kaya sumulat ng isang file bawat tala, tapos piliin silang lahat nang sabay kapag nag-i-import, o i-zip ang folder at piliin ang .zip.

Ang anyong buo pa rin pagdating

Dumarating sa JW Library bilang tunay na anyo ang mga talata, pagpapatid ng linya, bold, italic at bulleted na listahan. Ang mga ulo pagkatapos ng una ay nagiging karaniwang talata. Anumang kayang ipahayag ng Markdown na hindi kaya ng tala sa JW Library — mga talahanayan, larawan, link, code block — ay pinapaliit tungo sa teksto nito, kaya nananatili ang mga salita kahit hindi makasunod ang disenyo.

Kung nagsusulat ka na sa Obsidian

Markdown na ang mga file ng Obsidian, at ang Properties panel nito ay eksaktong nagsusulat ng front matter na inilalarawan dito: magdagdag ng property na tinatawag na publication na may halagang Matthew 26:39, at doon dadapo ang tala. Ang sariling property na tags ng Obsidian ay binabasa bilang tags. Ang mga link na nasa dobleng kuwadradong panaklong at ang mga naka-embed na tala ay pinapaliit tungo sa teksto nila, dahil walang matuturo ang mga iyon sa isang tala ng JW Library. Puwede mong piliin ang mga .md ng buong folder sa isang pag-import, o i-zip ang folder at ibigay ang .zip.

Kung nagsusulat ka na sa Notion

Kayang mag-export ng Markdown ng Notion: buksan ang menu ng pahina, piliin ang Export, at piliin ang “Markdown & CSV”. Ang lumalabas ay .zip, na tinatanggap ng pag-import kung ano ito. Isinusulat ng Notion ang pamagat ng pahina bilang ulo at ang sarili nitong mga property bilang karaniwang linya sa ilalim, at ang mga field na hindi nakikilala ng pag-import ay binabalewala sa halip na ituring na mali — kaya para mailagay ang tala sa isang teksto, ikaw na mismo ang magdagdag ng linyang publication sa itaas ng na-export na file.

Mga bagay na hindi mo kailangang matamaan nang tama

Walang kuwenta ang malalaking titik sa pangalan ng mga field. Puwedeng wala ang espasyo pagkatapos ng tutuldok. Binabalewala ang sobrang espasyo at tab, gayundin ang panipi sa palibot ng halaga at ang komentong nakasulat pagkatapos ng #. Ayos lang ang mga hangganan ng linya ng Windows. Puwede mo pa ngang tanggalin nang tuluyan ang mga linyang --- at simulan agad ang file sa mga field, basta't isa sa kanila ang pinakaunang linya. At kung mali ang baybay mo sa pangalan ng aklat — Mathew — sasabihin sa iyo ng pag-import na binasa niya iyon bilang Matthew 26:39 at maghihintay siyang lagyan mo ng tsek ang kahon, sa halip na magpasiya nang mag-isa.

Ang hindi gagawin ng pag-import sa aklatan mo

Nagdaragdag lang ang pag-import. Hindi ginagalaw ang mga tala, highlight, bookmark at tag na nasa backup mo na, at hindi kailanman binabago ang file na ini-load mo — sa huli ay magda-download ka ng bagong .jwlibrary at iyon ang ire-restore mo. Nilalaktawan ang talang ang pamagat, teksto at lugar ay tugmang-tugma sa isang bagay na nasa backup na, kaya ang pag-import ng parehong file nang dalawang beses ay walang idinodoble. Ang lahat ng idinaragdag ng pag-import ay isang hakbang lang ng Undo, at may tag na Imported ang mga na-import na tala, kaya mahahanap, masasala o matatanggal mo sila bilang grupo pagkatapos. Wala rito ang umaalis sa device mo.

Mga madalas itanong

Kailangan ko bang matuto muna ng Markdown?
Hindi. Wasto nang tala ang file na puro karaniwang pangungusap. Pumapasok lang ang Markdown kung gusto mo ng bold, italic o bullet, at kahit doon ay dalawang asterisk lang sa palibot ng salita para sa bold at isang gitling sa simula ng linya para sa bullet.
May kinalaman ba ang pangalan ng file?
Kapag lang walang sariling pamagat ang file. Kung walang linyang title: at walang ulong may #, nililinis ang pangalan ng file at iyon ang ginagamit, kaya ang ang-kopang-ipinanalangin-niya.md ay nagiging talang “ang kopang ipinanalangin niya”. Kung hindi naman, pangalanan mo ang file kung ano ang gusto mo.
Paano kung na-save ko itong .txt nang hindi sinasadya?
Palitan ang pangalan para magtapos ito sa .md at i-import ulit — walang kailangang baguhin sa laman. Sa Windows, baka kailangan mo munang buksan ang file name extensions sa View menu ng File Explorer, kung hindi ay nakatago sa iyo ang dulo.
Puwede ko bang isulat ang pangalan ng aklat sa sarili kong wika?
Sa ngayon ay hindi. Nakikilala ang pangalan ng aklat sa Ingles, at iyon din ang isinusulat ng Markdown export ng site na ito. Isulat ang tala sa kahit anong wikang gusto mo; ang linya lang ng reperensiya ang nangangailangan ng pangalang Ingles. Kung ayaw mo, laktawan ang reperensiya at ikaw na mismo ang maglagay nito sa lugar pagkatapos.
Puwede ba akong maglagay ng mahigit isang tala sa iisang file?
Hindi — nagiging isang tala ang bawat file. Pumili ng kasindami ng gusto mong file sa isang pag-import, o i-zip ang folder at piliin ang .zip.
Babaguhin ba nito ang mga talang mayroon na ako?
Hindi. Nagdaragdag lang ang pag-import. Hindi ginagalaw ang dati mong mga tala, at hindi kailanman binabago ang backup na ini-load mo: sa huli ay magda-download ka ng bagong file at ikaw ang magpapasiya kung ire-restore mo ito.
Ano ang mangyayari kung laktawan ko ang linya ng reperensiya?
Mai-import pa rin ang tala. Dumarating itong nakahiwalay na tala sa aklatan mo sa halip na nakakabit sa isang teksto — na siya namang karaniwang gusto ng talang tungkol sa isang pahayag, isang usapan, o isang personal na kaisipan.
