如何把 Markdown 筆記匯入 JW Library

把 Obsidian、Notion 或任何 Markdown 編輯器裡的 .md 檔案變成真正的 JW Library 筆記，並落在正確的經節上 — 免費、私密、全在瀏覽器裡完成。

JW Library 沒有任何把文字帶進來的方法。你可以在應用程式裡寫筆記，但在別處寫下的筆記 — 在 Obsidian、在 Notion、在電腦上的純文字檔案裡 — 根本沒有進入書庫的路。於是有人一條條重新打字，有人乾脆放棄，留下兩套永遠碰不到一起的研究筆記。

JW Sync 補上了這一段。在「研究瀏覽器」裡載入一個備份，按「匯入 Markdown」，你的 .md 檔案就會變成裡面真正的筆記：標題、日期和標籤原樣保留；如果檔案寫明屬於哪節經文，筆記就落在那一節上，跟你當初在應用程式裡邊讀邊寫完全一樣。

這在兩個方向上都成立。從本站匯出的筆記帶著書卷、章和節，所以會準確回到它們出來的地方。在別處寫的筆記通常沒有這些，所以本頁要講清楚那一兩行是怎麼把筆記安放到位的 — 以及檔案裡沒有它們時會怎樣。

逐步操作

  1. 在 JW Library 裡建立備份

    打開 JW Library，進入「個人研究」，點三點選單，選擇「備份和還原」，再選「建立備份」。這會得到一個 .jwlibrary 檔案 — 你的筆記將被加進這個書庫。

  2. 打開研究瀏覽器

    前往 jwsync.org，打開研究瀏覽器並載入那個 .jwlibrary 檔案。一切都在你的瀏覽器裡進行，檔案不會被上傳。

  3. 按「匯入 Markdown」

    按鈕就在「匯出 Markdown」旁邊。想選多少 .md 檔案都行，也可以選一個裝著它們的 .zip — 包括本站匯出時產生的那個 .zip。

  4. 在寫入任何東西之前先看摘要

    頁面會告訴你有多少則會落在經節上、有多少則會以獨立筆記加入、有多少則已在備份裡而被略過。凡是本站不得不做出判斷的，都會逐行列出並帶一個勾選框，讓你當場決定，而不是事後才發現。

  5. 匯出並還原

    按「匯出 .jwlibrary」，然後在 JW Library 的「備份和還原」→「還原」裡還原該檔案。匯入的筆記就成了這台裝置上書庫的一部分。

現在就試——免費，在瀏覽器裡完成JW Sync 完全在你的裝置上合併、編輯和分析 .jwlibrary 備份。不需要帳號，不上傳，不用安裝任何東西。開啟 JW Sync →

能用的最短檔案

一個 Markdown 檔案不需要任何東西就能被匯入：只有正文的檔案也會變成筆記，標題取自第一個標題行，沒有的話就取自檔名。其餘的一切都是為了說明這則筆記屬於哪裡。完整的檔案長這樣： --- title: 他禱告求的那杯 tags: [研究, 客西馬尼] publication: Matthew 26:39 --- 他的禱告表現的是順服，而不是不情願。 兩行短橫之間的部分叫 front matter，下面的行才是筆記本身。

會被讀取的欄位

只讀取五樣東西，而且每一樣都接受多種寫法，你不必記住某個確切的名字。**title**（或 name、heading）成為筆記標題。**tags**（或 tag、keywords、categories、labels、topics）成為真正的 JW Library 標籤，不存在就新建。**date**（或 created、modified）設定筆記日期；任何包含 YYYY-MM-DD 的值都能讀懂。**publication**（或 pub、reference、ref、scripture、citation、source、passage）是寫經文出處的地方。**book**、**chapter**、**verse**（或 ch、v、vs、verses）用分開的欄位做同一件事。你自己保留的其他欄位 — 作者、狀態、編輯器加的東西 — 會被忽略，而不會被當成錯誤。

把筆記指向經節的三種寫法

寫成一行：`publication: Matthew 26:39`。或者拆開：`book: Matthew`、`chapter: 26`、`verse: 39`。或者兩者都寫 — 本站的匯出就是這麼做的，這樣檔案對人好讀、對機器也精確。三種寫法結果相同，用最合你編輯器的那種即可。

經文出處可以寫得多隨意

書卷名的比對很寬容。全名可以，人們真正會打的縮寫也可以：Matt、Matt.、Mt、1 Cor、1Cor、I Corinthians、Second Timothy，Psalms 之外也認 Psalm，Song of Solomon 之外也認 Song of Songs。章與節之間的分隔可以是冒號、句點或字母 v — `John 3:16`、`John 3.16` 和 `1 Cor 13 v4` 讀法相同。空格處處可省，所以 `1Cor13:4` 也行。 front matter 本身同樣寬容。欄位名可以大寫。冒號後面的空格可以沒有。多餘的空格和定位字元會被忽略，值兩邊的引號和行尾的 # 註解也一樣。Windows 換行字元沒問題。你甚至可以完全省掉 --- 那兩行，直接以欄位開頭，只要第一行是能辨識的欄位名 — 這條規矩是為了讓一則以帶冒號的普通句子開頭的筆記不會掉了第一段。

標籤，怎麼寫都行

下面幾種寫法都會得到同樣的兩個標籤：`tags: [研究, 希臘語]`、`tags: 研究, 希臘語`、`tags: 研究; 希臘語`、`tags: #研究 #希臘語`，或者在 `tags:` 下面另起幾行、每行以短橫開頭的清單。書庫裡已有的標籤會被沿用而不是重複建立，所以匯入的筆記會歸到你平時篩選用的那個標籤底下。

遇到不確定時會怎樣

任何拿不準的事都不會替你決定。如果書卷名接近某個真實的名字但並不一致 — `Mathew`、`Ecclesiates` — 筆記不會被自動放置。它會單獨佔一行出現在摘要裡，寫明本站是怎麼讀的：「讀作 Matthew 26:39」，並帶一個勾選框。取消勾選就不匯入；保留勾選就按那一行落位。 如果書卷完全無法辨識，那一行會說明這一點，筆記會以獨立筆記加入 — 絕不會被硬套到一個猜測上。帶編號的書卷會保住編號，所以 `1 Jonh` 只可能被更正為約翰一書，絕不會變成約翰二書。

刻意不做的事

節的範圍會把筆記錨在第一節：`Matthew 26:39-41` 會把筆記放在第 39 節，因為 JW Library 的筆記附著在正文的一個點上，而不是一段區間。只有章沒有節的出處 — `Matthew 26` — 會把筆記附到那一章。寫的是出版物而不是經文的檔案 — `The Watchtower—2023 No. 4` — 會以普通的獨立筆記匯入，不會多問一句，因為本站的匯出為文章裡所記的筆記寫的正是這個。

能撐過這趟旅程的格式

段落、換行、**粗體**、*斜體*和項目符號清單，到了 JW Library 裡仍是真正的格式。檔案開頭的標題會被當作筆記標題，而不會在正文裡重複一遍。Markdown 表達得了而 JW Library 筆記表達不了的東西 — 表格、圖片、連結、程式碼區塊 — 會被簡化為文字，所以即便版面帶不過去，字句一個也不會少。

筆記究竟落到哪裡，以及為什麼這樣是安全的

要把筆記附到某節經文上，JW Library 需要那一章的內部識別碼，而它們因你的書庫而異。JW Sync 從不憑空編造。它會沿用你自己的備份裡已有的那一章的位置，或者從同一個檔案裡另一處聖經位置複製這些識別碼。如果一個備份裡根本沒有任何聖經筆記或標記，就無處可抄 — 那麼這些筆記會以獨立筆記加入，而不是附到應用程式可能認不出的東西上。這是有意的取捨：一則悄無聲息落錯地方的筆記，比一則明明白白沒有附著的筆記更糟。

把同樣的檔案匯入兩次

當標題、正文和位置都與備份裡的某則一致時，這則筆記會被視作已經存在，所以把同一批匯出再匯入一次不會多出任何東西。在你確認之前，摘要會告訴你有多少則因此被略過。一次匯入所加的一切算作一步「復原」，匯入的筆記還會帶上 Imported 標籤，方便你日後整批尋找、篩選或刪除。

常見問題

一定要寫 --- 那兩行嗎？
不必。它們讓檔案毫無歧義，任何 Markdown 編輯器也都認得，但你也可以直接以欄位開頭 — 第一行寫 `title: …` — 或者乾脆不寫 front matter，讓筆記從第一個標題行取標題。
如果我把書卷名拼錯了呢？
本站通常能看出你的意思，但不會僅憑這一點就動手。那則筆記會出現在摘要裡，寫明它是怎麼被讀的，並帶勾選框，讓你在任何東西被寫入之前先確認。
可以匯入整個 Obsidian 資料夾嗎？
一次想選多少 .md 檔案都行，或者把資料夾壓縮成 .zip 再選它。壓縮檔裡的檔案和散落的檔案讀法完全一樣。
匯入會覆蓋我已有的筆記嗎？
不會。匯入只做新增。你現有的筆記、標記、書籤和標籤都不會被動，載入的檔案也從不被修改 — 最後你下載的是一個新的 .jwlibrary。
我的筆記會被上傳到哪裡嗎？
不會。和本站其他功能一樣，全部在你的瀏覽器裡執行。備份和 Markdown 檔案都不會離開你的裝置。
經文出處可以用哪種語言寫？
目前書卷名按英文辨識，匯出時寫的也是英文。如果你用別的語言記筆記，請在 `book`、`chapter`、`verse` 欄位裡填英文書卷名，或者先不附著地匯入，之後再手動安放。
筆記還能再匯出來嗎？
可以 — 同一個畫面裡的「匯出 Markdown」會把每則筆記寫成帶同樣欄位的 .md 檔案，所以筆記可以離開 JW Library 再回來，而不失去它所屬的位置。
