用 Library Doctor 修復損壞的 JW Library 備份

JW Library 不肯還原你的 .jwlibrary 檔案？Library Doctor 會在你的瀏覽器裡掃描這個備份，修復常見問題，並生成一個能正常還原的乾淨副本。

一個還原不了的備份，不一定就是一個已經丟了筆記的備份。人們口中「損壞」的檔案，大多結構完好，只是因為某個可修復的原因被拒絕，或者是在傳輸中受損、換一份新的就好了。在給這個檔案判死刑之前，值得先把各種原因過一遍。

有時候 JW Library 會拒絕一個備份檔案——還原失敗、報錯，或者檔案根本打不開。常見原因有：下載中斷、雲盤把檔案搞壞了、副檔名在傳輸途中被改掉，或者多年使用中積累下來的內部不一致。

JW Sync 內建了 Library Doctor：一個檢查工具，它掃描 .jwlibrary 檔案並修復常見問題——完全在你的瀏覽器裡進行，檔案絕不離開你的裝置。

逐步操作

  1. 開啟 JW Sync，載入有問題的檔案

    去 jwsync.org，載入那個還原不了的 .jwlibrary 檔案。（如果檔案到手時被改名成了 .zip，先改回 .jwlibrary——光是這一步就能解決不少情況。）

  2. 執行 Library Doctor 掃描

    Doctor 會檢查備份的內部結構，並用大白話列出它發現的一切——從無害的小毛病到真正的損壞。

  3. 應用程式修復

    點一下就修好所有可修的地方。Doctor 絕不改動你的原始檔案；它生成的是一個清理過的副本，原件原封不動地留著當退路。

  4. 下載並還原修復後的檔案

    在 JW Library 裡透過備份和還原 → 還原，把清理過的 .jwlibrary 裝回去。

現在就試——免費，在瀏覽器裡完成JW Sync 完全在你的裝置上合併、編輯和分析 .jwlibrary 備份。不需要帳號，不上傳，不用安裝任何東西。開啟 JW Sync →

每次合併時 Doctor 也會跑一遍

同樣的檢查會在合併引擎內部自動執行，所以合併出來的備份始終是乾淨的——哪怕其中一個輸入檔案有你從來不知道的問題。

當一個檔案真的修不好了

如果檔案被截斷得太厲害，資料根本就不在裡面，那麼任何工具都變不出來。Doctor 會老老實實告訴你，而不是生成一個可疑的檔案——那就是去郵件、Drive 或 iCloud 裡翻找更早副本的訊號，這也是為什麼留著舊備份是值得的。

「損壞」通常意味著什麼

實際上很少是資料本身壞了。常見的原因是檔案在傳輸中被截斷——上傳失敗或者聊天應用程式壓縮了它——或者壓縮包完好但裡面存在應用程式不接受的內部不一致。因為 .jwlibrary 檔案是一個包著 SQLite 資料庫的 ZIP，兩層裡的任何一層都可能出問題，而它們需要不同的處理。被截斷的檔案修不好，只能重新弄一份；不一致的資料庫通常修得好。

一次掃描到底檢查了什麼

掃描會確認壓縮包打得開，userData.db 是一個能讀、能透過完整性檢查的 SQLite 資料庫，表結構符合 JW Library 的預期，以及清單檔案和它所描述的資料庫彼此吻合——包括應用程式用來確認檔案未被改動的那個雜湊值。清單與資料庫對不上，是一個技術上完好的備份在還原時被拒絕的最常見原因之一，而且修起來很直接。

孤立的記錄行通常無害

掃描一個真實的備份，常常會報出一些指向已不存在之物的記錄行——比如一處標註指著一個已經挪走的出版物位置。JW Library 自己做的備份裡動輒有幾百條這種東西，還原起來毫無怨言。它們是出版物隨時間更新的正常結果，不是損壞的證據，清不清掉都不影響檔案能不能用。

從一個還原不了的檔案裡搶救筆記

即使一個備份修不到 JW Library 肯接受的程度，裡面的筆記往往仍然讀得出來。在瀏覽器裡開啟這個檔案，你可以直接看到並複製筆記正文，這就把一個用不了的檔案變成了搶救回來的研讀材料。如果你還有另一個較舊、能正常還原的備份，從損壞檔案裡讀出來的內容可以跟它匯到一起，而不必重新打一遍。

還原失敗但沒有明確報錯時

JW Library 經常在拒絕一個檔案時不解釋原因。最常見的幾種情況是：清單裡的雜湊值與它所描述的資料庫對不上；檔案在傳輸中被截斷；或者備份是由比你要還原進去的那個版本更新的應用程式寫出來的。第一種修得好，第二種需要從原始來源重新取一次檔案，第三種在還原前把應用程式更新一下就解決了。

下次怎麼避免

大多數損壞發生在傳輸途中。請把備份當作檔案來搬，而不要經過任何可能重新壓縮它的東西，優先用雲端儲存、AirDrop 或資料線，少用聊天應用程式。傳完之後確認檔案大小和原件一致——比你發出去的明顯小一截，就說明被截斷了，而任何修復都變不回從未到達的位元組。

如果什麼辦法都不行

一個修不好的檔案仍然可能讀得出來，而讀得出來往往就夠了——即便 JW Library 拒絕這個檔案，筆記正文還是能直接取回。把它和任何一個能正常還原的舊備份合起來，你通常還是能保住書庫的大部分。在斷定一個檔案沒救之前，先開啟它，看看裡面究竟有什麼。

常見問題

掃描時我的資料會被上傳嗎？
不會。掃描、修復和匯出全都在瀏覽器本地執行。
它能找回我在 JW Library 裡刪掉的筆記嗎？
不能——它修的是檔案結構。在做備份之前就已經在應用程式裡刪掉的筆記，本來就不在檔案裡，也就無從找回。
修復檔案會丟掉筆記嗎？
修復是在副本上進行的，處理的是結構問題而不是內容。你的原始檔案絕不會被改動，所以隨時可以推倒重來。
我的備份為什麼會損壞？
最常見的是檔案在傳輸中被改動了——經過某個壓縮或截斷了它的應用程式，或者上傳沒有完成。從原始來源重新傳一次通常就能解決。
掃描能找回我在 JW Library 裡刪掉的筆記嗎？
不能。一旦在應用程式裡刪掉並做了新備份，那條筆記在這個檔案裡就沒有了。刪除之前做的舊備份裡仍然會有。
能從檔案大小看出它是不是被截斷了嗎？
常常可以。如果原件還在，拿來比一比；明顯短了一截就說明傳輸沒有完成。
能在瀏覽器裡開啟的備份，就一定能還原嗎？
不能保證，但這是壓縮包和資料庫都完好的有力訊號，最常見的幾種失敗也就排除了。
