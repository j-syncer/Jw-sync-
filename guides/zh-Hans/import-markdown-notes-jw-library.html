如何把 Markdown 笔记导入 JW Library

把 Obsidian、Notion 或任何 Markdown 编辑器里的 .md 文件变成真正的 JW Library 笔记，并落在正确的经节上 — 免费、私密、全在浏览器里完成。

JW Library 没有任何把文字带进来的方法。你可以在应用里写笔记，但在别处写下的笔记 — 在 Obsidian、在 Notion、在电脑上的纯文本文件里 — 根本没有进入书库的路。于是有人一条条重新打字，有人干脆放弃，留下两套永远碰不到一起的研究笔记。

JW Sync 补上了这一段。在“研究浏览器”里载入一个备份，按“导入 Markdown”，你的 .md 文件就会变成里面真正的笔记：标题、日期和标签原样保留；如果文件写明属于哪节经文，笔记就落在那一节上，跟你当初在应用里边读边写完全一样。

这在两个方向上都成立。从本站导出的笔记带着书卷、章和节，所以会准确回到它们出来的地方。在别处写的笔记通常没有这些，所以本页要讲清楚那一两行是怎么把笔记安放到位的 — 以及文件里没有它们时会怎样。

分步操作

  1. 在 JW Library 里创建备份

    打开 JW Library，进入“个人研究”，点三点菜单，选择“备份和恢复”，再选“创建备份”。这会得到一个 .jwlibrary 文件 — 你的笔记将被加进这个书库。

  2. 打开研究浏览器

    访问 jwsync.org，打开研究浏览器并载入那个 .jwlibrary 文件。一切都在你的浏览器里进行，文件不会被上传。

  3. 按“导入 Markdown”

    按钮就在“导出 Markdown”旁边。想选多少 .md 文件都行，也可以选一个装着它们的 .zip — 包括本站导出时生成的那个 .zip。

  4. 在写入任何东西之前先看摘要

    页面会告诉你有多少条会落在经节上、有多少条会作为独立笔记加入、有多少条已在备份里而被跳过。凡是本站不得不做出判断的，都会逐行列出并带一个勾选框，让你当场决定，而不是事后才发现。

  5. 导出并恢复

    按“导出 .jwlibrary”，然后在 JW Library 的“备份和恢复”→“恢复”里恢复该文件。导入的笔记就成了这台设备上书库的一部分。

现在就试——免费，在浏览器里完成JW Sync 完全在你的设备上合并、编辑和分析 .jwlibrary 备份。不需要账号，不上传，不用安装任何东西。打开 JW Sync →

能用的最短文件

一个 Markdown 文件不需要任何东西就能被导入：只有正文的文件也会变成笔记，标题取自第一个标题行，没有的话就取自文件名。其余的一切都是为了说明这条笔记属于哪里。完整的文件长这样： --- title: 他祷告求的那杯 tags: [研究, 客西马尼] publication: Matthew 26:39 --- 他的祷告表现的是顺服，而不是不情愿。 两行短横之间的部分叫 front matter，下面的行才是笔记本身。

会被读取的字段

只读取五样东西，而且每一样都接受多种写法，你不必记住某个确切的名字。**title**（或 name、heading）成为笔记标题。**tags**（或 tag、keywords、categories、labels、topics）成为真正的 JW Library 标签，不存在就新建。**date**（或 created、modified）设定笔记日期；任何包含 YYYY-MM-DD 的值都能读懂。**publication**（或 pub、reference、ref、scripture、citation、source、passage）是写经文出处的地方。**book**、**chapter**、**verse**（或 ch、v、vs、verses）用分开的字段做同一件事。你自己保留的其他字段 — 作者、状态、编辑器加的东西 — 会被忽略，而不会被当成错误。

把笔记指向经节的三种写法

写成一行：`publication: Matthew 26:39`。或者拆开：`book: Matthew`、`chapter: 26`、`verse: 39`。或者两者都写 — 本站的导出就是这么做的，这样文件对人好读、对机器也精确。三种写法结果相同，用最合你编辑器的那种即可。

经文出处可以写得多随意

书卷名的匹配很宽容。全名可以，人们真正会打的缩写也可以：Matt、Matt.、Mt、1 Cor、1Cor、I Corinthians、Second Timothy，Psalms 之外也认 Psalm，Song of Solomon 之外也认 Song of Songs。章与节之间的分隔可以是冒号、句点或字母 v — `John 3:16`、`John 3.16` 和 `1 Cor 13 v4` 读法相同。空格处处可省，所以 `1Cor13:4` 也行。 front matter 本身同样宽容。字段名可以大写。冒号后面的空格可以没有。多余的空格和制表符会被忽略，值两边的引号和行尾的 # 注释也一样。Windows 换行符没问题。你甚至可以完全省掉 --- 那两行，直接以字段开头，只要第一行是能识别的字段名 — 这条规矩是为了让一条以带冒号的普通句子开头的笔记不会丢掉第一段。

标签，怎么写都行

下面几种写法都会得到同样的两个标签：`tags: [研究, 希腊语]`、`tags: 研究, 希腊语`、`tags: 研究; 希腊语`、`tags: #研究 #希腊语`，或者在 `tags:` 下面另起几行、每行以短横开头的列表。书库里已有的标签会被沿用而不是重复创建，所以导入的笔记会归到你平时筛选用的那个标签下。

遇到不确定时会怎样

任何拿不准的事都不会替你决定。如果书卷名接近某个真实的名字但并不一致 — `Mathew`、`Ecclesiates` — 笔记不会被自动放置。它会单独占一行出现在摘要里，写明本站是怎么读的：“读作 Matthew 26:39”，并带一个勾选框。取消勾选就不导入；保留勾选就按那一行落位。 如果书卷完全无法识别，那一行会说明这一点，笔记会作为独立笔记加入 — 绝不会被硬套到一个猜测上。带编号的书卷会保住编号，所以 `1 Jonh` 只可能被更正为约翰一书，绝不会变成约翰二书。

刻意不做的事

节的范围会把笔记锚在第一节：`Matthew 26:39-41` 会把笔记放在第 39 节，因为 JW Library 的笔记附着在正文的一个点上，而不是一段区间。只有章没有节的出处 — `Matthew 26` — 会把笔记附到那一章。写的是出版物而不是经文的文件 — `The Watchtower—2023 No. 4` — 会作为普通的独立笔记导入，不会多问一句，因为本站的导出为文章里所记的笔记写的正是这个。

能撑过这趟旅程的格式

段落、换行、**粗体**、*斜体*和项目符号列表，到了 JW Library 里仍是真正的格式。文件开头的标题会被当作笔记标题，而不会在正文里重复一遍。Markdown 表达得了而 JW Library 笔记表达不了的东西 — 表格、图片、链接、代码块 — 会被简化为文字，所以即便版式带不过去，字句一个也不会少。

笔记究竟落到哪里，以及为什么这样是安全的

要把笔记附到某节经文上，JW Library 需要那一章的内部标识，而它们因你的书库而异。JW Sync 从不凭空编造。它会沿用你自己的备份里已有的那一章的位置，或者从同一个文件里另一处圣经位置复制这些标识。如果一个备份里根本没有任何圣经笔记或标记，就无处可抄 — 那么这些笔记会作为独立笔记加入，而不是附到应用可能认不出的东西上。这是有意的取舍：一条悄无声息落错地方的笔记，比一条明明白白没有附着的笔记更糟。

把同样的文件导入两次

当标题、正文和位置都与备份里的某条一致时，这条笔记会被视作已经存在，所以把同一批导出再导入一次不会多出任何东西。在你确认之前，摘要会告诉你有多少条因此被跳过。一次导入所加的一切算作一步“撤销”，导入的笔记还会带上 Imported 标签，方便你日后整批查找、筛选或删除。

常见问题

一定要写 --- 那两行吗？
不必。它们让文件毫无歧义，任何 Markdown 编辑器也都认得，但你也可以直接以字段开头 — 第一行写 `title: …` — 或者干脆不写 front matter，让笔记从第一个标题行取标题。
如果我把书卷名拼错了呢？
本站通常能看出你的意思，但不会仅凭这一点就动手。那条笔记会出现在摘要里，写明它是怎么被读的，并带勾选框，让你在任何东西被写入之前先确认。
可以导入整个 Obsidian 文件夹吗？
一次想选多少 .md 文件都行，或者把文件夹压缩成 .zip 再选它。压缩包里的文件和散落的文件读法完全一样。
导入会覆盖我已有的笔记吗？
不会。导入只做添加。你现有的笔记、标记、书签和标签都不会被动，载入的文件也从不被修改 — 最后你下载的是一个新的 .jwlibrary。
我的笔记会被上传到哪里吗？
不会。和本站其他功能一样，全部在你的浏览器里运行。备份和 Markdown 文件都不会离开你的设备。
经文出处可以用哪种语言写？
目前书卷名按英文识别，导出时写的也是英文。如果你用别的语言记笔记，请在 `book`、`chapter`、`verse` 字段里填英文书卷名，或者先不附着地导入，之后再手动安放。
笔记还能再导出来吗？
可以 — 同一个界面里的“导出 Markdown”会把每条笔记写成带同样字段的 .md 文件，所以笔记可以离开 JW Library 再回来，而不丢失它所属的位置。
