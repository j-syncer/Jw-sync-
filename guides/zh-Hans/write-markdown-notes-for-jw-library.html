如何写出能导入 JW Library 的 Markdown 文件

在记事本、TextEdit 或 Obsidian 里写一条笔记，让它落在 JW Library 里正确的那节经文上。到底要敲哪几行，以及哪些可以不写。

JW Sync 能把 Markdown 文件读进 JW Library 的备份里。知道有这个功能之后，真正要紧的就只剩一个问题：那个文件该长什么样？这一页从写的人这一边来回答——不是导入能接受什么，而是你实际要敲什么。

简短的说法是：一条笔记就是一个文本文件。新建文件，写好笔记，存成 .md 结尾，它就能导入。这一页其余的内容都围绕着一行可写可不写的字：那一行说明这条笔记属于哪节经文，好让它在你读到那节经文时出现在 JW Library 里，而不是孤零零地夹在你其他笔记中间。

这些都不需要 Markdown 编辑器，也不需要你去学 Markdown。Windows 的记事本和 Mac 的 TextEdit 就够了。如果你本来就把研究笔记放在 Obsidian 或 Notion 里，那些文件本身就是 Markdown，下面各有一节专门讲。

分步操作

  1. 打开任何一个纯文本编辑器

    Windows 的记事本、Mac 的 TextEdit，或者你本来就在用的 Markdown 应用——Obsidian、Typora、iA Writer、Joplin 都行。唯一要避开的是文字处理软件：Word 和 Google 文档保存的是排版和格式而不是纯文本，两者都做不出导入能读的文件。

  2. 把笔记敲进去

    第一行写标题，前面加一个 #，空一行，再在下面写笔记正文。这样就已经是一个完整、有效的文件了。要是你连标题那行都不想写，那就会改用文件名。

  3. 存成 .md 结尾

    名字随你取——我的笔记.md。在 Windows 上，除非你先把“保存类型”改成“所有文件”，否则记事本会存成 .txt，这一步是最常出错的地方。在 Mac 上，保存前先选“格式”，再选“制作纯文本”。

  4. 加上那一行，把它放到经文上

    在文件的最上面、所有内容之前，写一行三个短横，然后写 publication: Matthew 26:39，再写一行三个短横。这条笔记现在就挂在那节经文上了。不写也没关系，笔记照样能导入——只是进来的时候没有挂在任何地方。

  5. 把它导入一个备份

    在 JW Library 里进入个人研究，打开三点菜单，选择备份与恢复，创建一个备份。把那个文件加载到 jwsync.org 的研究浏览器里，按“导入 Markdown”，选上你的 .md 文件，然后读一读在写入任何东西之前给你看的摘要。之后按“导出 .jwlibrary”，再在 JW Library 里恢复那个文件。

能用的最短文件

一个除了文字什么都没有的文件，本身就已经是一条有效的笔记。全部内容就这些：

# 他祷告求的那杯

他的祷告表现的是顺服，而不是不情愿。

以 # 开头的那行会变成笔记的标题，它下面的一切会变成笔记正文。这个文件导入起来毫无问题。它只是作为一条独立的笔记进来，夹在你其他笔记里，而不是挂在某节经文上。

在 Windows 上做这个文件

打开记事本，敲好笔记，然后选“文件”和“另存为”。保存前把“保存类型”从“文本文档”改成“所有文件”——少了这一步，记事本会悄悄补上 .txt，你手里剩下的就是我的笔记.md.txt，而导入是看不见它的。然后再输入以 .md 结尾的名字。Windows 可能会警告说改扩展名可能让文件不可用；恰恰是这个警告，说明你做对了。

在 Mac 上做这个文件

打开 TextEdit，在敲任何字之前，先选“格式”，再选“制作纯文本”。TextEdit 一开始处在富文本模式，保存的是 .rtf，那根本不是文本文件。切到纯文本模式之后，选“文件”和“存储”，让名字以 .md 结尾。如果 macOS 提出要替你补上 .txt，拒绝它。

在手机或平板上做这个文件

任何能保存或导出 Markdown 的应用都行——Obsidian、Bear、iA Writer、Joplin，Android 上的 Markor。iPhone 和 Android 自带的备忘录应用一般存不了 .md 文件，所以在手机上通常要么用上面这些应用，要么干脆在电脑上写。导入的时候你可以一次选很多个文件，整个文件夹也可以打包成一个 .zip 交上去。

把笔记放到经文上的那一行

所有告诉导入这条笔记属于哪里的内容，都放在文件最上面的一小块里，夹在两行三个短横之间。这一块叫 front matter，对多数笔记来说只有一行：

---
publication: Matthew 26:39
---

# 他祷告求的那杯

他的祷告表现的是顺服，而不是不情愿。

这条笔记现在挂在马太福音 26:39 上了。你读到那节经文时，它会出现在 JW Library 里，就跟你当初在应用里当场写下的一模一样。

把经文出处写成能被读懂的样子

书卷名要用英文写，哪怕笔记本身是别的语言：写 Matthew，不要写马太福音。人们真正会敲的缩写也认得——Matt、Matt.、Mt、1 Cor、1Cor、I Corinthians、Second Timothy。章和节之间可以用冒号、句点或者字母 v，所以 John 3:16、John 3.16 和 1 Cor 13 v4 意思一样，空格也可有可无，1Cor13:4 同样可以。像 Matthew 26:39-41 这样的范围，会把笔记放在头一节也就是 39 节上，因为 JW Library 的笔记挂在正文里的某一个点上，而不是挂在一段范围上。

完整的文件：带标题、日期和标签

如果你想要，还有三行可以用，而且每一行都可以不写：

---
title: 他祷告求的那杯
date: 2026-08-15
tags: [研究, 客西马尼]
publication: Matthew 26:39
---

他的祷告表现的是顺服，而不是不情愿。

title 和带 # 的标题作用一样，所以两者写一个就够。date 决定笔记的日期，免得留下你导入那天的日期。tags 会变成真正的 JW Library 标签，可以用来筛选，你已经有的标签会被沿用而不是重复建一个。tags 那一行也可以写成不带方括号的 研究, 客西马尼，或者 #研究 #客西马尼，或者在下面另起几行写成短横列表——这四种写法读出来都一样。

一个文件一条笔记

每个 .md 文件都会变成一条笔记。没有办法把好几条笔记塞进同一个文件再让它们拆开，因为 Markdown 文件里没有任何东西能可靠地标出一条笔记在哪里结束、下一条在哪里开始——半路上的一个标题，可能是第二条笔记，也可能只是第一条的小标题，猜错了就会把你写的东西打散。所以一条笔记写一个文件，导入时一次全选，或者把文件夹打包，选那个 .zip。

能完好送到的格式

段落、换行、粗体、斜体和项目符号列表，到了 JW Library 里都是真正的格式。第一个标题之后的标题会变成普通段落。凡是 Markdown 表达得了而 JW Library 笔记表达不了的东西——表格、图片、链接、代码块——都会缩成它的文字，所以即便版式跟不上，字句仍然保得住。

如果你本来就在 Obsidian 里写

Obsidian 的文件本身就是 Markdown，它的属性面板写出来的正是这里说的 front matter：加一个叫 publication 的属性，值填 Matthew 26:39，笔记就会落到那里。Obsidian 自己的 tags 属性会被当作 tags 读。双方括号的链接和嵌入的笔记会缩成文字，因为 JW Library 的笔记没有地方可以让它们指过去。你可以在一次导入里选中整个文件夹的 .md 文件，也可以把文件夹打包，交那个 .zip。

如果你本来就在 Notion 里写

Notion 可以导出 Markdown：打开页面菜单，选 Export，再选“Markdown & CSV”。出来的是一个 .zip，导入原样就能收。Notion 会把页面标题写成标题，把它自己的属性写成下面的普通行，而导入不认得的字段会被略过，不会当成错误——所以要把笔记放到经文上，你自己在导出的文件顶部补一行 publication 就行。

不必较真的地方

字段名的大小写无所谓。冒号后面的空格可以没有。多余的空格和制表符会被略过，值两边的引号和写在 # 后面的注释也一样。Windows 的换行没问题。你甚至可以把两行 --- 全部省掉，直接从字段开始写，只要第一行是其中之一就行。而且要是你把书卷名拼错了——比如 Mathew——导入会告诉你它把这读成了 Matthew 26:39，然后等你打勾，而不是自己拿主意。

导入不会对你的书库做的事

导入只会添加。备份里已有的笔记、标记、书签和标签都不会被动，你加载的那个文件也从不会被改动——最后你下载的是一个新的 .jwlibrary，恢复的也是它。一条笔记如果标题、正文和位置都跟备份里已有的东西对得上，就会被跳过，所以同样的文件导两遍也不会多出什么。一次导入添加的全部内容，撤销一步就能退回去，而且导入的笔记都带着 Imported 标签，方便你以后找出来、筛选或者整组删掉。这些事情没有一样会离开你的设备。

常见问题

我得先学会 Markdown 吗？
不用。一个只有普通句子的文件就已经是有效的笔记了。只有当你想要粗体、斜体或者项目符号时才会用到 Markdown，就算那时候，也不过是给一个词两边各加两个星号表示粗体，在行首写一个短横表示一个项目。
文件名要紧吗？
只有在文件本身没有标题的时候才要紧。既没有 title: 那一行，也没有带 # 的标题时，文件名会被整理一下拿来用，所以 他祷告求的那杯.md 会变成一条叫“他祷告求的那杯”的笔记。除此之外，文件名随你取。
要是我不小心存成了 .txt 呢？
把名字改成以 .md 结尾，再导入一次就行——内容一个字都不用动。在 Windows 上你可能得先到文件资源管理器的“查看”菜单里打开文件扩展名，不然结尾那一截是看不见的。
书卷名可以用我自己的语言写吗？
目前不行。书卷名是按英文识别的，本站的 Markdown 导出写的也是英文。笔记正文你想用什么语言都可以，只有写出处的那一行需要英文名。要是不愿意这样，就把出处那行省掉，之后再手动把笔记放到位置上。
我能把好几条笔记放进同一个文件吗？
不能——每个文件都会变成一条笔记。一次导入里想选多少个文件都行，或者把文件夹打包，选那个 .zip。
这会改动我已有的笔记吗？
不会。导入只会添加。你原有的笔记不会被动，你加载的备份也从不会被改动：最后你下载的是一个新文件，要不要恢复由你决定。
如果我不写出处那一行会怎样？
笔记照样能导入。它会作为一条独立的笔记进到你的书库里，而不是挂在某节经文上——而关于演讲、谈话或者个人想法的笔记，通常本来就该是这样。
