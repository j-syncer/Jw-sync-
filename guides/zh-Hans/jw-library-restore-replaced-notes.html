还原把你的笔记覆盖了？教你把两个备份合起来

JW Library 的还原是整体替换，不是合并——备份日期之后写的笔记看起来没了。只要两个备份文件都还在，其实什么都没丢。补救方法在这里。

那是很难受的一刻：你把一个备份还原到一台本来就有笔记的设备上，还原替换了所有内容——你在那次备份之后写的笔记看起来消失了。会这样是因为 JW Library 的「备份和还原」是整体替换，不是合并。

关键的一点：只要那些较新的成果还存在于某个备份文件里，就其实什么都没丢。补救办法是把两个备份合并起来，而不是在它们之间二选一。

分步操作

  1. 停——先别再还原

    每一次还原都会替换设备当前的数据。在更多东西消失之前先停下来。

  2. 把设备现在的状态备份下来

    个人研究 → 备份和还原 → 创建备份。不管里面现在是什么，先把当前状态保住。

  3. 找出含有那些「消失」笔记的备份

    就是你还原时用的那个 .jwlibrary 文件，或者更早的一个——查一查邮件、Drive、iCloud 和下载文件夹。

  4. 在 jwsync.org 合并这两个文件

    把两个备份都载入。JW Sync 会把两边所有的笔记、标注、书签和标签合并成一个新文件——在你的浏览器里完成，什么都不上传。同一条笔记有冲突的版本会并排显示，由你挑选。

  5. 还原合并后的文件

    用合并后的 .jwlibrary 走一次备份和还原 → 还原。两边的笔记都回到设备上了。

如果较新的笔记根本没有备份怎么办？

如果那些较新的笔记只存在于设备上，而还原已经把它们盖掉了，JW Library 本身不提供撤销。这正是上面第 2 步——在做任何事之前先把当前状态备份下来——在数据看起来不对劲时如此要紧的原因。往后养成「先合并再还原」的习惯，这个问题在结构上就不可能再发生。

常见问题

合并会不会把两个备份共有的笔记变成两份？
不会——完全相同的项目会被识别出来，只保留一份。只有同一条笔记确实不同的版本才会被标出来供你审阅。
