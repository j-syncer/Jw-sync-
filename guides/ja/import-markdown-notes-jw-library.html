Markdown のノートを JW Library に読み込む方法

Obsidian や Notion などの Markdown エディタで書いた .md ファイルを、正しい節に付いた本物の JW Library のノートに変換します。無料・非公開・ブラウザの中だけで完結します。

JW Library には、外からテキストを取り込む手段がありません。アプリの中でノートを書くことはできますが、ほかの場所で書いたノート — Obsidian、Notion、パソコンのテキストファイル — には、ライブラリへ入る道が一切ないのです。結局は手で打ち直すか、あきらめて、決して交わらない二組の研究ノートを抱えることになります。

JW Sync がその隙間を埋めます。「研究エクスプローラー」にバックアップを読み込み、「Markdown を読み込む」を押すと、.md ファイルがその中の本物のノートになります。表題・日付・タグはそのまま残り、どの聖句に属するかがファイルに書かれていれば、その節に付きます。読みながらアプリでノートを書いたのと同じ状態です。

これは双方向に働きます。このサイトから書き出したノートには書名・章・節が入っているので、出てきた場所へ正確に戻ります。ほかで書いたノートには普通そうした情報がありません。だからこのページでは、ノートを置くための一、二行と、その行がないファイルがどうなるかを説明します。

手順

  1. JW Library でバックアップを作る

    JW Library を開き、「個人研究」から三点メニューをタップ、「バックアップと復元」→「バックアップを作成」を選びます。.jwlibrary ファイルができます。これがノートの追加先になるライブラリです。

  2. 研究エクスプローラーを開く

    jwsync.org を開き、研究エクスプローラーでその .jwlibrary ファイルを読み込みます。すべてブラウザの中で行われ、ファイルがアップロードされることはありません。

  3. 「Markdown を読み込む」を押す

    ボタンは「Markdown を書き出し」の隣にあります。.md ファイルは何個でも選べますし、それらをまとめた .zip でもかまいません。このサイトが書き出す .zip もそのまま使えます。

  4. 何かが書き込まれる前に要約を読む

    何件が節に付き、何件が単独のノートとして追加され、何件がすでにバックアップにあって飛ばされるかが表示されます。サイトが解釈せざるを得なかったものは一行ずつチェック欄付きで並びます。後から気づくのではなく、その場で決められます。

  5. 書き出して復元する

    「.jwlibrary を書き出し」を押し、そのファイルを JW Library の「バックアップと復元」→「復元」から復元します。読み込んだノートが、その端末のライブラリの一部になります。

今すぐどうぞ — 無料、ブラウザーの中でJW Sync は .jwlibrary バックアップの統合・編集・分析を、すべてあなたの端末で行います。アカウント不要、アップロードなし、インストール不要です。JW Sync を開く →

いちばん短い、それでも通るファイル

Markdown ファイルは、読み込まれるだけなら何も要りません。本文だけのファイルもノートになり、表題は最初の見出しから、なければファイル名から取られます。それ以外はすべて「ノートがどこに属するか」を伝えるためのものです。完全なファイルはこうなります。 --- title: 彼が祈った杯 tags: [研究, ゲッセマネ] publication: Matthew 26:39 --- この祈りは、いやいやではなく従順を示している。 二本のハイフン行に挟まれた部分を front matter と呼びます。その下の行がノート本文です。

読み取られる項目

読み取られるのは五つだけで、それぞれ複数の書き方を受け付けるので、正確な名前を覚える必要はありません。**title**（または name、heading）はノートの表題になります。**tags**（または tag、keywords、categories、labels、topics）は JW Library の本物のタグになり、なければ作られます。**date**（または created、modified）はノートの日付です。YYYY-MM-DD を含む値なら理解されます。**publication**（または pub、reference、ref、scripture、citation、source、passage）に聖句を書きます。**book**、**chapter**、**verse**（または ch、v、vs、verses）は同じことを別々の項目で行います。ほかの項目 — 著者、状態、エディタが付け足すもの — は、エラーとして扱われるのではなく、単に無視されます。

ノートを節に結び付ける三つの方法

一行で書く：`publication: Matthew 26:39`。分けて書く：`book: Matthew`、`chapter: 26`、`verse: 39`。両方書く — このサイトの書き出しがそうしています。人が読んでも分かりやすく、機械にとっても厳密だからです。三つとも結果は同じなので、お使いのエディタに合う書き方をどうぞ。

聖句の書き方はどこまで大まかでよいか

書名は寛容に照合されます。正式名はもちろん、実際に打たれる略記も通ります。Matt、Matt.、Mt、1 Cor、1Cor、I Corinthians、Second Timothy、Psalms だけでなく Psalm、Song of Solomon だけでなく Song of Songs。章と節の区切りはコロンでも、ピリオドでも、v でもかまいません。`John 3:16`、`John 3.16`、`1 Cor 13 v4` はすべて同じに読まれます。空白は省いてよいので `1Cor13:4` でも通ります。 front matter 自体も同じくらい寛容です。項目名は大文字でもかまいません。コロンの後の空白はなくても大丈夫。余分な空白やタブ、値を囲む引用符、行末の # コメントも無視されます。Windows の改行も問題ありません。--- の行を丸ごと省いて、いきなり項目から書き始めることもできます。ただし最初の一行が認識できる項目名であることが条件です。これは、コロンを含むふつうの文で始まるノートが最初の段落を失わないための決まりです。

タグは、どう書いても構いません

次のどれもが同じ二つのタグになります。`tags: [研究, ギリシャ語]`、`tags: 研究, ギリシャ語`、`tags: 研究; ギリシャ語`、`tags: #研究 #ギリシャ語`、あるいは `tags:` の下に行を分け、各項目をハイフンで始めた並び。すでにライブラリにあるタグは重複して作られず再利用されるので、読み込んだノートは、ふだん絞り込みに使っているのと同じタグに加わります。

はっきりしないときにどうなるか

あいまいなことが勝手に決められることはありません。書名が実在のものに近いけれど一致しない場合 — `Mathew`、`Ecclesiates` — ノートは自動的には置かれません。要約に一行として現れ、サイトがどう読んだかを示します。「Matthew 26:39 と解釈しました」とチェック欄付きで。外せばそのノートは見送られ、付けたままなら行の通りに置かれます。 書名がまったく判別できない場合は、その旨が表示され、ノートは単独のノートとして追加されます。推測に無理やり合わせることはありません。番号付きの書は番号を保つので、`1 Jonh` はヨハネ第一にしか直されず、ヨハネ第二になることはありません。

あえてしないこと

節の範囲は最初の節に結び付けられます。`Matthew 26:39-41` はノートを 39 節に置きます。JW Library のノートは範囲ではなく本文の一点に付くからです。章はあって節のない聖句 — `Matthew 26` — はその章に結び付きます。聖句ではなく出版物名を書いたファイル — `The Watchtower—2023 No. 4` — は、何も尋ねられずにふつうの単独ノートとして読み込まれます。記事で取ったノートに対して、このサイトの書き出しがまさにそう書くからです。

旅を生き延びる書式

段落、改行、**太字**、*斜体*、箇条書きは、JW Library でも本物の書式として現れます。ファイル先頭の見出しはノートの表題として使われ、本文の中で繰り返されることはありません。Markdown では表せても JW Library のノートでは表せないもの — 表、画像、リンク、コードブロック — は文字だけに縮められます。体裁は引き継げなくても、言葉が失われることはありません。

ノートが実際にどこへ行くのか、そしてなぜ安全なのか

ノートを節に付けるには、その章についての内部識別子が必要で、それはあなたのライブラリ固有のものです。JW Sync がそれを創作することはありません。その章についてあなたのバックアップがすでに持っている位置を再利用するか、同じファイル内の別の聖句の位置からその識別子を写します。バックアップに聖書のノートもハイライトもまったくない場合は、写す元がないため、アプリが認識しないかもしれないものに付けるのではなく、単独のノートとして追加します。これは意図した選択です。黙って誤った場所に着いたノートは、はっきり未接続で届いたノートより悪いのです。

同じファイルを二度読み込む

表題・本文・場所がバックアップ内の何かと一致するノートは、すでにあるものとして扱われます。同じ書き出しをもう一度読み込んでも二重にはなりません。確定前に、その理由で飛ばされる件数が要約に出ます。読み込みが加えたものはすべて「元に戻す」一回分で、読み込まれたノートには Imported というタグが付くので、後からまとめて探し、絞り込み、削除できます。

よくある質問

--- の行は必ず要りますか。
いいえ。ファイルを曖昧さなく示せますし、どの Markdown エディタも理解しますが、いきなり項目から始めても — 一行目を `title: …` にしても — 構いませんし、front matter を書かずに最初の見出しを表題にさせることもできます。
書名を打ち間違えたら。
たいていサイトは意図を汲みますが、それだけで動くことはありません。ノートは要約に、どう読んだかとチェック欄付きで現れ、何かが書き込まれる前にあなたが確認します。
Obsidian のフォルダごと読み込めますか。
.md ファイルは一度に何個でも選べますし、フォルダを圧縮して .zip を選んでも構いません。書庫の中のファイルも、単独のファイルと同じように読まれます。
読み込むと今あるノートが上書きされますか。
いいえ。読み込みは追加するだけです。既存のノート、ハイライト、しおり、タグはそのままで、読み込んだファイルも変更されません。最後に新しい .jwlibrary をダウンロードします。
ノートはどこかへ送られますか。
いいえ。このサイトのほかの機能と同じく、すべてブラウザの中で動きます。バックアップも Markdown ファイルも端末から出ません。
聖句はどの言語で書けますか。
現在、書名は英語で認識されます。書き出しも英語で書きます。ほかの言語でノートを書いている場合は、`book`、`chapter`、`verse` の項目に英語の書名を入れるか、結び付けずに読み込んで後から手で置いてください。
ノートをまた取り出せますか。
はい。同じ画面の「Markdown を書き出し」が、各ノートを同じ項目付きの .md ファイルに書き出します。ノートは JW Library から出て、また戻ることができ、所属する場所を失いません。
