JW Library に読み込める Markdown ファイルの書き方

メモ帳・TextEdit・Obsidian で書いたノートを、JW Library の正しい聖句に載せる方法。実際に打ち込む行と、省いてよいものを説明します。

JW Sync は Markdown ファイルを JW Library のバックアップに読み込めます。その機能を知ったとき本当に問題になるのは一つだけ——ファイルはどんな形でなければならないのか、ということです。このページは書く側から答えます。読み込み側が何を受け付けるかではなく、あなたが実際に何を打ち込むかです。

短く言えば、ノートとはテキストファイルです。ファイルを作り、ノートを書き、末尾を .md にして保存すれば、それで読み込めます。ここから先はすべて、省いてもよい一行についての説明です。そのノートがどの聖句に属するかを示す行で、これがあるとノートはあなたの他のノートに埋もれず、JW Library でその聖句を読んでいるときに現れます。

Markdown エディタは要りません。Markdown を覚える必要もありません。Windows のメモ帳、Mac の TextEdit で十分です。すでに Obsidian や Notion で研究ノートを取っているなら、そのファイルはもう Markdown です。それぞれの節が下にあります。

手順

  1. プレーンテキストのエディタを開く

    Windows ならメモ帳、Mac なら TextEdit、あるいはすでに使っている Markdown アプリ——Obsidian、Typora、iA Writer、Joplin などです。避けたいのはワープロだけです。Word や Google ドキュメントはプレーンテキストではなく書式やレイアウトを保存するので、どちらも読み込みが読めるファイルにはなりません。

  2. ノートを打ち込む

    1 行目に # を付けてタイトルを書き、1 行空けて、その下にノートを書きます。これでもう完全な、有効なファイルです。タイトル行を書きたくなければ、代わりにファイル名が使われます。

  3. .md を付けて保存する

    名前は何でも構いません——マイノート.md のように。Windows のメモ帳は、先に「ファイルの種類」を「すべてのファイル」に変えないと .txt で保存します。ここが一番間違えやすいところです。Mac では保存前に「フォーマット」から「標準テキストにする」を選びます。

  4. 聖句に載せる行を足す

    ファイルのいちばん上、他のすべてより前に、ハイフン 3 つの行、publication: Matthew 26:39、そしてまたハイフン 3 つの行を書きます。これでノートはその聖句に結び付きました。省いてもノートは読み込まれます——ただ、どこにも結び付かない状態で入るだけです。

  5. バックアップに読み込む

    JW Library で「個人研究」を開き、三点メニューから「バックアップと復元」を選んでバックアップを作ります。そのファイルを jwsync.org の研究エクスプローラーに読み込ませ、「Markdown を読み込み」を押し、.md ファイルを選び、何かが書き込まれる前に表示される要約を読みます。そのうえで「.jwlibrary を書き出し」を押し、JW Library でそのファイルを復元します。

今すぐどうぞ — 無料、ブラウザーの中でJW Sync は .jwlibrary バックアップの統合・編集・分析を、すべてあなたの端末で行います。アカウント不要、アップロードなし、インストール不要です。JW Sync を開く →

いちばん短い、それでも通るファイル

テキストしか入っていないファイルでも、すでに有効なノートです。これで全部です。

# 彼が祈った杯

この祈りは、いやいやではなく従順を示している。

# で始まる行がノートのタイトルになり、その下がすべてノート本文になります。このファイルは何の文句もなく読み込まれます。ただ、聖句に結び付かない独立したノートとして、他のノートに並んで入るだけです。

Windows でファイルを作る

メモ帳を開いてノートを打ち込み、「ファイル」から「名前を付けて保存」を選びます。保存する前に「ファイルの種類」を「テキスト文書」から「すべてのファイル」に変えてください。この手順を飛ばすとメモ帳は黙って .txt を足し、マイノート.md.txt になってしまい、読み込みからは見えません。そのうえで .md で終わる名前を入力します。拡張子を変えるとファイルが使えなくなるかもしれない、と Windows が警告することがありますが、その警告こそ正しくできた印です。

Mac でファイルを作る

TextEdit を開き、何かを打ち込む前に「フォーマット」から「標準テキストにする」を選びます。TextEdit はリッチテキストモードで起動し、.rtf で保存しますが、これはそもそもテキストファイルではありません。標準テキストモードにしたら「ファイル」から「保存」を選び、名前を .md で終わらせます。macOS が .txt を付け足そうと申し出たら断ってください。

スマートフォンやタブレットでファイルを作る

Markdown を保存または書き出せるアプリなら何でも使えます——Obsidian、Bear、iA Writer、Joplin、Android なら Markor など。iPhone や Android に最初から入っているメモアプリはたいてい .md ファイルを保存できないので、スマートフォンではこうしたアプリを使うか、素直にパソコンで書くのが普通の道です。読み込むときは何ファイルでも一度に選べますし、フォルダごと zip にして一つの .zip として渡すこともできます。

ノートを聖句に載せる、たった一行

ノートがどこに属するかを読み込みに伝えるものは、すべてファイルのいちばん上、ハイフン 3 つの行 2 本にはさまれた小さなブロックに入れます。これを front matter と呼び、たいていのノートでは一行で足ります。

---
publication: Matthew 26:39
---

# 彼が祈った杯

この祈りは、いやいやではなく従順を示している。

このノートはこれでマタイ 26:39 に結び付きました。その聖句を読んでいるあいだ JW Library に現れます——アプリの中でそこに書いたのと、まったく同じように。

理解される書き方で聖句を書く

書名は英語で書いてください。ノート本文が別の言語でも同じです——マタイではなく Matthew です。人が実際に打ち込む略記も通じます——Matt、Matt.、Mt、1 Cor、1Cor、I Corinthians、Second Timothy。章と節のあいだはコロン、ピリオド、あるいは文字 v が使えるので、John 3:16、John 3.16、1 Cor 13 v4 はどれも同じ意味になります。スペースは省けるので 1Cor13:4 でも構いません。Matthew 26:39-41 のような範囲指定は、最初の節である 39 節にノートを置きます。JW Library のノートは範囲ではなく本文の一点に結び付くからです。

タイトル・日付・タグ付きの完全なファイル

望むならあと 3 行使えます。どれも省いて構いません。

---
title: 彼が祈った杯
date: 2026-08-15
tags: [研究, ゲッセマネ]
publication: Matthew 26:39
---

この祈りは、いやいやではなく従順を示している。

title は # の見出しと同じ働きなので、どちらか一方で足ります。date は読み込んだ日ではなくノートの日付を決めます。tags は絞り込みに使える本物の JW Library のタグになり、すでにあるタグは重複させずに再利用されます。tags の行は、角かっこなしで 研究, ゲッセマネ と書いても、#研究 #ゲッセマネ と書いても、下に行を分けてハイフンの箇条書きにしても構いません——4 通りとも同じに読まれます。

1 ファイルに 1 ノート

.md ファイル 1 つがノート 1 つになります。1 つのファイルに複数のノートを入れて分割させることはできません。Markdown ファイルの中には、どこでノートが終わり次が始まるかを確実に示すものが何もないからです——途中の見出しは 2 つ目のノートかもしれませんし、1 つ目の小見出しかもしれません。取り違えれば書いたものが散らばってしまいます。ですからノートごとにファイルを分け、読み込むときにまとめて選ぶか、フォルダを zip にして .zip を選んでください。

そのまま届く書式

段落、改行、太字、斜体、箇条書きは、JW Library に本物の書式として届きます。最初の見出しより後の見出しは普通の段落になります。Markdown で表せて JW Library のノートでは表せないもの——表、画像、リンク、コードブロック——はテキストに落とし込まれるので、レイアウトが付いていけないところでも言葉は残ります。

すでに Obsidian で書いている場合

Obsidian のファイルはもう Markdown で、そのプロパティ欄はここで説明した front matter をそのまま書き出します。publication というプロパティに Matthew 26:39 という値を入れれば、ノートはそこに着きます。Obsidian 自身の tags プロパティは tags として読まれます。二重角かっこのリンクや埋め込みノートはテキストに落とし込まれます。JW Library のノートには、それらを指し示す先がないからです。フォルダ 1 つ分の .md を一度の読み込みで選ぶことも、フォルダを zip にして .zip を渡すこともできます。

すでに Notion で書いている場合

Notion は Markdown で書き出せます。ページのメニューを開き、「エクスポート」を選び、「Markdown & CSV」を指定してください。出てくるのは .zip で、読み込みはそのまま受け付けます。Notion はページタイトルを見出しとして、自身のプロパティを下の普通の行として書き出しますが、読み込みが知らない項目はエラー扱いではなく無視されます。ですからノートを聖句に載せたいときは、書き出したファイルの先頭に publication の行を自分で足してください。

きちんと合わせなくてよいこと

項目名の大文字小文字は関係ありません。コロンの後のスペースはなくても構いません。余分なスペースやタブは無視され、値を囲む引用符や # の後に書いたコメントも同じです。Windows の改行でも問題ありません。--- の行をまるごと省いて、いきなり項目からファイルを始めることさえできます。いちばん最初の行が項目のどれかでありさえすればよいのです。そして書名を打ち間違えても——Mathew のように——読み込みは「Matthew 26:39 と読みました」と伝え、あなたがチェックを入れるのを待ちます。勝手に決めることはありません。

読み込みがあなたのライブラリーにしないこと

読み込みは足すだけです。バックアップにすでにあるノート、ハイライト、しおり、タグには手を触れませんし、読み込ませたファイルが書き換えられることもありません——最後に新しい .jwlibrary をダウンロードし、それを復元します。タイトル・本文・位置がバックアップの中の何かと一致するノートは飛ばされるので、同じファイルを二度読み込んでも重複しません。読み込みが足したものはすべて「元に戻す」一回分で、読み込まれたノートには Imported というタグが付くので、後から探すことも、絞り込むことも、まとめて消すこともできます。そのどれもが端末の外には出ません。

よくある質問

先に Markdown を覚える必要がありますか。
いいえ。普通の文が並んだファイルで、すでに有効なノートです。Markdown が関わるのは太字・斜体・箇条書きが欲しいときだけで、それも太字は語をアスタリスク 2 つで囲む、箇条書きは行頭にハイフンを置く、というだけです。
ファイル名は関係ありますか。
ファイル自体にタイトルがないときだけです。title: の行も # の見出しもない場合、ファイル名が整えられて代わりに使われるので、彼が祈った杯.md は「彼が祈った杯」というノートになります。それ以外なら名前は自由です。
うっかり .txt で保存してしまったら。
.md で終わるように名前を変えて、もう一度読み込んでください。中身は何も変えなくて構いません。Windows では先にエクスプローラーの「表示」メニューでファイル名拡張子を表示させないと、末尾が見えないことがあります。
書名を自分の言語で書けますか。
今のところできません。書名は英語で認識され、このサイトの Markdown 書き出しもそう書きます。ノート本文は好きな言語で構いません。英語名が要るのは聖句の行だけです。それが嫌なら聖句の行を省き、あとから手で位置を決めてください。
1 つのファイルに複数のノートを入れられますか。
いいえ——1 ファイルが 1 ノートになります。一度の読み込みで好きなだけファイルを選ぶか、フォルダを zip にして .zip を選んでください。
今あるノートが変わってしまいますか。
いいえ。読み込みは足すだけです。今あるノートには手を触れませんし、読み込ませたバックアップが書き換えられることもありません。最後に新しいファイルをダウンロードし、復元するかどうかはあなたが決めます。
聖句の行を省くとどうなりますか。
ノートはそれでも読み込まれます。聖句に結び付くのではなく、独立したノートとしてライブラリーに入ります——話や会話、個人的な考えについてのノートなら、たいていそれこそが望ましい形です。
