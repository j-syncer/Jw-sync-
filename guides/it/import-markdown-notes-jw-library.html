Come importare note Markdown in JW Library

Trasforma i file .md di Obsidian, Notion o qualsiasi editor Markdown in vere note di JW Library, collocate sul versetto giusto — gratis, privato, nel browser.

JW Library non ha alcun modo di far entrare del testo. Puoi scrivere note dentro l'app, ma una nota scritta altrove — in Obsidian, in Notion, in un semplice file di testo sul computer — non ha alcuna strada verso la tua biblioteca. Si finisce per ribatterle a mano, oppure si rinuncia e si tengono due insiemi di note di studio che non si incontrano mai.

JW Sync colma questo vuoto. Carica un backup nell'Esploratore di studio, premi «Importa Markdown» e i tuoi file .md diventano note vere al suo interno: titolo, data ed etichette intatti e — quando il file dice a quale passo appartiene — legate a quel versetto, esattamente come se avessi scritto la nota nell'app mentre lo leggevi.

Funziona nei due sensi. Le note esportate da questo sito portano con sé libro, capitolo e versetto, quindi tornano esattamente da dove sono partite. Le note scritte altrove di solito non portano niente del genere, ed è per questo che questa pagina spiega le una o due righe che le collocano — e cosa succede quando un file non le ha.

Passo passo

  1. Crea un backup in JW Library

    Apri JW Library, vai in Studio personale, tocca il menu a tre puntini, scegli Backup e ripristino e poi Crea un backup. Ottieni un file .jwlibrary: la biblioteca a cui verranno aggiunte le tue note.

  2. Apri l'Esploratore di studio

    Vai su jwsync.org, apri l'Esploratore di studio e carica quel file .jwlibrary. Tutto avviene dentro il browser; il file non viene mai caricato da nessuna parte.

  3. Premi «Importa Markdown»

    Il pulsante sta accanto a «Esporta Markdown». Scegli tutti i file .md che vuoi, oppure uno .zip che li contiene — compreso lo .zip che questo sito produce quando esporti.

  4. Leggi il riepilogo prima che venga scritto qualcosa

    Ti viene detto quante note finiranno su un versetto, quante saranno aggiunte come note libere e quante sono già nel backup e verranno saltate. Tutto ciò che il sito ha dovuto interpretare è elencato riga per riga, con una casella, così decidi tu invece di scoprirlo dopo.

  5. Esporta e ripristina

    Premi «Esporta .jwlibrary» e ripristina quel file in JW Library da Backup e ripristino → Ripristina. Le note importate ora fanno parte della tua biblioteca su quel dispositivo.

Fallo ora — gratis, nel tuo browserJW Sync unisce, modifica e analizza i backup .jwlibrary interamente sul tuo dispositivo. Senza account, senza caricamenti, senza installare nulla.Apri JW Sync →

Il file più corto che funziona

Un file Markdown non ha bisogno di nulla per essere importato: un file con solo testo diventa una nota e prende il titolo dalla prima intestazione o, se manca, dal nome del file. Tutto il resto serve a dire dove va la nota. Un file completo si presenta così: --- title: Il calice per cui pregò tags: [studio, getsemani] publication: Matthew 26:39 --- La sua preghiera mostra sottomissione, non riluttanza. Il blocco fra le due righe di trattini si chiama front matter. Le righe sotto sono la nota vera e propria.

I campi che vengono letti

Vengono lette solo cinque cose, e ognuna accetta più nomi così non devi ricordarne uno esatto. **title** (o name, heading) diventa il titolo della nota. **tags** (o tag, keywords, categories, labels, topics) diventano vere etichette di JW Library, create se non esistono ancora. **date** (o created, modified) imposta la data della nota; si capisce qualunque valore contenga AAAA-MM-GG. **publication** (o pub, reference, ref, scripture, citation, source, passage) è dove scrivi il passo. **book**, **chapter** e **verse** (o ch, v, vs, verses) fanno lo stesso in campi separati. Qualsiasi altro campo che tieni per tuo uso — autore, stato, quello che aggiunge il tuo editor — viene ignorato anziché trattato come errore.

Tre modi per puntare una nota a un versetto

Scrivi il riferimento su una riga: `publication: Matthew 26:39`. Oppure scomponilo: `book: Matthew`, `chapter: 26`, `verse: 39`. Oppure usa entrambi — è ciò che fa l'esportazione di questo sito, così il file si legge bene per una persona e si analizza con precisione per una macchina. Tutti e tre danno lo stesso risultato: usa quello che si adatta al tuo editor.

Quanto può essere approssimativo il riferimento

I nomi dei libri sono riconosciuti con larghezza. Funzionano i nomi completi e anche le abbreviazioni che la gente digita davvero: Matt, Matt., Mt, 1 Cor, 1Cor, I Corinthians, Second Timothy, Psalm oltre a Psalms, Song of Songs oltre a Song of Solomon. Il separatore fra capitolo e versetto può essere due punti, un punto o la lettera v — `John 3:16`, `John 3.16` e `1 Cor 13 v4` si leggono allo stesso modo. Gli spazi sono facoltativi, quindi va bene anche `1Cor13:4`. Il front matter è altrettanto tollerante. I nomi dei campi possono avere maiuscole. Lo spazio dopo i due punti può mancare. Spazi e tabulazioni in eccesso vengono ignorati, così come le virgolette attorno ai valori e un commento finale con #. I fine riga di Windows non danno problemi. Puoi perfino omettere le righe --- e iniziare il file direttamente con i campi, purché la primissima riga sia uno dei nomi riconosciuti: questa regola esiste perché una nota che comincia con una frase normale contenente i due punti non perda il primo paragrafo.

Le etichette, comunque tu le scriva

Tutte queste forme producono le stesse due etichette: `tags: [studio, greco]`, `tags: studio, greco`, `tags: studio; greco`, `tags: #studio #greco`, oppure un elenco su righe proprie sotto `tags:` con ogni voce che inizia con un trattino. Le etichette già presenti nella tua biblioteca vengono riutilizzate anziché duplicate, quindi la nota importata entra nella stessa etichetta con cui già filtri.

Cosa succede quando qualcosa non è chiaro

Nulla di incerto viene deciso al posto tuo. Se il nome di un libro somiglia a uno vero ma non è esatto — `Mathew`, `Ecclesiates` — la nota non viene collocata automaticamente. Compare nel riepilogo, su una riga tutta sua, con ciò che il sito ne ha ricavato: «letto come Matthew 26:39», con una casella. Toglila e la nota resta fuori; lasciala e va dove dice la riga. Se il libro non viene riconosciuto affatto, la riga lo dice e la nota viene aggiunta come nota libera — mai forzata su una supposizione. Un libro numerato conserva il numero, quindi `1 Jonh` può solo diventare 1 Giovanni, mai 2 Giovanni.

Ciò che deliberatamente non fa

Un intervallo di versetti àncora la nota al primo: `Matthew 26:39-41` la colloca al versetto 39, perché una nota di JW Library si attacca a un punto del testo e non a un tratto. Un riferimento con il capitolo ma senza versetto — `Matthew 26` — attacca la nota a quel capitolo. Un file che nomina una pubblicazione invece di un passo — `The Watchtower—2023 No. 4` — viene importato come normale nota libera senza domande, perché è esattamente ciò che l'esportazione di questo sito scrive per le note prese in un articolo.

La formattazione che sopravvive al viaggio

Paragrafi, ritorni a capo, **grassetto**, *corsivo* ed elenchi puntati arrivano in JW Library come vera formattazione. Un'intestazione in cima al file viene usata come titolo della nota invece di essere ripetuta al suo interno. Tutto ciò che Markdown sa esprimere e le note di JW Library no — tabelle, immagini, collegamenti, blocchi di codice — viene ridotto al suo testo: nessuna parola va persa, anche quando l'impaginazione non può essere mantenuta.

Dove finiscono davvero le note, e perché è sicuro

Per attaccare una nota a un versetto, JW Library ha bisogno di identificatori interni di quel capitolo, propri della tua biblioteca. JW Sync non se li inventa mai. Riutilizza la posizione che il tuo backup ha già per quel capitolo, oppure copia quegli identificatori da un'altra posizione biblica nello stesso file. Se un backup non contiene alcuna nota o evidenziazione nella Bibbia, non c'è nulla da cui copiare: le note vengono allora aggiunte come note libere invece di essere attaccate a qualcosa che l'app potrebbe non riconoscere. È una scelta voluta: una nota che finisce silenziosamente nel posto sbagliato è peggio di una che arriva dichiaratamente slegata.

Importare due volte gli stessi file

Una nota è considerata già presente quando titolo, testo e posizione coincidono con qualcosa nel backup: reimportare la stessa esportazione non raddoppia nulla. Il riepilogo ti dice quante verranno saltate per questo motivo prima che confermi. Tutto ciò che un'importazione aggiunge è un solo passo di Annulla, e le note importate ricevono l'etichetta «Imported», così poi puoi trovarle, filtrarle o eliminarle in blocco.

Domande frequenti

Devo per forza usare le righe ---?
No. Rendono il file inequivocabile e ogni editor Markdown le capisce, ma puoi anche iniziare il file direttamente con i campi — `title: …` sulla prima riga — o fare a meno del front matter e lasciare che la nota prenda il titolo dalla prima intestazione.
E se sbaglio il nome di un libro?
Di solito il sito capisce cosa intendevi, ma non agisce solo per questo. La nota compare nel riepilogo con la lettura scelta e una casella, così confermi prima che venga scritto qualcosa.
Posso importare un'intera cartella di Obsidian?
Seleziona in una volta tutti i file .md che vuoi, oppure comprimi la cartella e scegli lo .zip. I file al suo interno vengono letti come quelli sciolti.
L'importazione sovrascriverà le note che ho già?
No. L'importazione aggiunge soltanto. Le tue note, evidenziazioni, segnalibri ed etichette restano intatti, e il file che hai caricato non viene mai modificato: alla fine scarichi un nuovo .jwlibrary.
Le mie note vengono caricate da qualche parte?
No. Tutto gira nel tuo browser, come il resto del sito. Né il backup né i file Markdown lasciano il tuo dispositivo.
In che lingua posso scrivere il riferimento?
Per ora i nomi dei libri sono riconosciuti in inglese, che è anche ciò che scrive l'esportazione. Se tieni le note in un'altra lingua, usa i campi `book`, `chapter` e `verse` con il nome inglese del libro, oppure importa le note slegate e collocale a mano più tardi.
Posso far uscire di nuovo le mie note?
Sì — «Esporta Markdown», nella stessa schermata, scrive ogni nota in un file .md con gli stessi campi: le note possono uscire da JW Library e rientrare senza perdere il posto a cui appartengono.
